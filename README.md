# FraudGuard — анти-фрод скоринг-движок

Учебный консольный прототип для анализа синтетических транзакций: правила + статистический профиль клиента → риск-скор 0–100 → `APPROVE` / `REVIEW` / `BLOCK` → отчёты CSV.

> Это учебная модель, не предназначенная для реальных платёжных решений. Все данные в каталоге `data/` синтетические.

## С чего начать

1. Прочитать [`VISION.md`](VISION.md) и [`docs/requirements.md`](docs/requirements.md).
2. Использовать [`docs/decision-log.md`](docs/decision-log.md) как единый журнал согласованных решений.
3. Проверить эталонные данные в [`data/`](data/) и ожидаемые результаты в `data/expected-results.csv`.
4. После проектирования реализовать и проверить C++ и Kotlin версии по одним требованиям.

## Каталоги

- `docs/` — требования, решения, схема CSV, сценарии тестирования и UML.
- `data/` — синтетические входные и эталонные данные.
- `cpp/` — основная реализация C++17 и Google Test.
- `kotlin/` — порт бизнес-логики и тесты JUnit/Kotest.
- `reports/` — создаваемые `results.csv`, `alerts.csv`, `errors.csv`.

## Правила скоринга

- `HIGH_AMOUNT`: +30.
- `UNUSUAL_AMOUNT`: +15, взаимоисключающее с `HIGH_AMOUNT`.
- `HIGH_VELOCITY`: +25.
- `NEW_COUNTRY`: +20.
- `NEW_DEVICE`: +15.
- `NEW_CATEGORY`: +10.

`MIN_HISTORY_SIZE = 5`; сумма факторов ограничивается 100. Решения: 0–29 `APPROVE`, 30–59 `REVIEW`, 60–100 `BLOCK`. Точные условия определены в `docs/requirements.md`.
