# Проверка архитектурных решений перед реализацией

Перед началом реализации команда должна проверить следующие контракты:

- [ ] Весь скоринг опирается на правила и пороги из `requirements.md`.
- [ ] Профиль ключуется одновременно по `client_id` и `currency`.
- [ ] История используется только для профиля, новые транзакции — для результата и частотного окна.
- [ ] `HIGH_AMOUNT` и `UNUSUAL_AMOUNT` не срабатывают одновременно.
- [ ] `HIGH_VELOCITY` учитывает все валидные входные попытки в окне `[t - 10 min, t]`.
- [ ] Ошибочная строка не получает `APPROVE` и не попадает в `results.csv`.
- [ ] `alerts.csv` содержит только `REVIEW` и `BLOCK`.
- [ ] C++ и Kotlin используют одинаковую формулу медианы, метод P95 и денежную точность.
- [ ] Выходные CSV корректно экранируют запятые, кавычки и переводы строк в текстовых полях.

После проверки архитектуры можно приступать к реализации моделей и ProfileBuilder.
