# Проверка архитектурных решений

В реализации C++ этапа 3 выполнена сверка основных контрактов. При портировании на Kotlin нужно сохранить эти решения.

- [x] Весь скоринг опирается на правила и пороги из `requirements.md`.
- [x] Профиль ключуется одновременно по `client_id` и `currency`.
- [x] История используется только для профиля; новые транзакции — для результата и частотного окна.
- [x] `HIGH_AMOUNT` и `UNUSUAL_AMOUNT` не срабатывают одновременно.
- [x] `HIGH_VELOCITY` использует валидные новые попытки в закрытом временном окне `[t - 10 min, t]`.
- [x] Ошибочная строка не получает `APPROVE` и не попадает в `results.csv`.
- [x] `alerts.csv` содержит только `REVIEW` и `BLOCK`.
- [x] Медиана, nearest-rank P95, пороги и денежная интерпретация описаны для повторения в Kotlin.
- [x] Выходные CSV корректно экранируют запятые, кавычки и переводы строк в текстовых полях.

**Следующий шаг:** реализация Kotlin должна пройти общие тестовые сценарии и совпасть с C++ на `transaction_id`, `risk_score`, `decision`, `risk_factors` и `profile_status`.
