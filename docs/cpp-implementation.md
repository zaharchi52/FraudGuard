# Этап 3 — реализация ядра на C++17

## Состав модулей

| Файл | Назначение |
|---|---|
| `cpp/include/fraudguard/engine.hpp` | Модели транзакции, профиля, факторов риска, результата и публичные функции скоринга. |
| `cpp/src/engine.cpp` | Медиана, P95, профиль клиента, шесть правил, расчёт скора, решение и координация пакетной обработки. |
| `cpp/include/fraudguard/csv_io.hpp` | Интерфейс загрузки транзакций и записи отчётов. |
| `cpp/src/csv_io.cpp` | CSV-парсер с кавычками/экранированием, валидация, уникальность ID и CSV-отчёты. |
| `cpp/src/main.cpp` | Командная строка и запуск приложения. |
| `cpp/tests/engine_tests.cpp` | Unit-тесты Google Test для статистики, дат, статусов профиля, правил и порогов решений. |
| `cpp/tests/smoke_tests.cpp` | Автономные smoke-тесты без внешних библиотек. |

## Ключевые решения

- Используется C++17 и стандартная библиотека; внешняя библиотека для CSV не нужна. Парсер поддерживает запятые и кавычки внутри полей, удвоенные кавычки и переводы строк внутри цитируемого поля.
- Для `timestamp` требуется ISO 8601 с часовым поясом. Внутреннее значение времени представлено в миллисекундах; дробные секунды точнее миллисекунд усекаются до первых трёх знаков. Это достаточно для заданного минутного окна и позволяет правильно сравнивать границу интервала с миллисекундной точностью.
- Денежная сумма читается как конечное положительное число. Сравнение статистики выполняется по `client_id` и валюте; разные валюты не смешиваются.
- `MIN_HISTORY_SIZE = 5`. Медиана для чётного числа значений — среднее двух центральных; P95 — nearest-rank `ceil(0.95 * n)`.
- `HIGH_AMOUNT` применяется при `amount >= 5 * median`, иначе может примениться `UNUSUAL_AMOUNT` при `amount > P95`. Одновременно эти два правила не срабатывают.
- `HIGH_VELOCITY` считает валидные новые транзакции клиента в закрытом интервале `[t - 10 минут, t]`, включая текущую. Сначала время всех валидных строк сортируется; поэтому результат не зависит от порядка строк во входном файле, а `results.csv` сохраняет исходный порядок. История в частотное окно не включается.
- Ошибка строки записывается в `errors.csv`, а обработка продолжается. Повторный ID проверяется между историческими и новыми транзакциями. Некорректная строка не получает бизнес-решение и не попадает в `results.csv`.
- Отсутствующая история не завершает программу: выводится предупреждение, профили получают `COLD_START`, профильные правила не применяются.
- Выходные CSV записываются с заголовками, полями в заданном порядке и корректным экранированием специальных символов.

## Проверка этапа

Проверены сборка CMake, CTest и запуск на `data/transactions.csv`. Девять транзакций скорируются; три попадают в алерты, ошибок нет. Поля `transaction_id`, `risk_score`, `decision`, `risk_factors` и `profile_status` совпадают с `data/expected-results.csv`.

На `data/transactions_invalid.csv` три некорректные строки записываются в `errors.csv`, при этом корректная транзакция `T9004` обрабатывается. В окружении без установленного Google Test CMake выполняет автономные smoke-тесты; полный набор `engine_tests.cpp` включён и автоматически используется там, где Google Test установлен.

## Ограничения учебной версии

- Нет банковских интеграций, ML-модели, базы данных или онлайн-обработки.
- Нет конвертации валют; статистика строится по каждой валюте отдельно.
- Внутреннее представление суммы использует `long double`; для промышленной финансовой системы предпочтительнее точный decimal/minor-units контракт, одинаково реализованный в C++ и Kotlin.
- `BLOCK` — демонстрационная рекомендация, а не команда реальному платёжному сервису.
