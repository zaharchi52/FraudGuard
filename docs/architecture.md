# Архитектура FraudGuard

**Уровень:** учебный проект  
**Назначение документа:** объяснить устройство программы простыми словами и связать диаграммы с реальными файлами проекта.

## 1. Общая идея

FraudGuard получает два CSV-файла:

- `history.csv` — предыдущие операции клиента (необязательный файл);
- `transactions.csv` — новые операции для проверки.

Программа проверяет строки, анализирует каждую новую транзакцию и присваивает ей риск-скор от 0 до 100. Затем выбирает рекомендацию `APPROVE`, `REVIEW` или `BLOCK` и формирует отчёты.

Проект содержит три реализации одной логики:

| Реализация | Для чего нужна |
|---|---|
| **C++17** | Пакетный движок: читает CSV из файлов и сохраняет отчёты. |
| **Kotlin + Swing** | Настольное приложение: показывает имитацию ленты, очередь `REVIEW` и позволяет запускать C++-движок. |
| **Dart + Flutter Web** | Браузерное приложение с похожей лентой, ручной проверкой и экспортом CSV. |

Все три реализации учебные. Они не подключаются к банку и не управляют реальными платежами.

## 2. Как проходит обработка

1. Пользователь выбирает CSV с новыми транзакциями и, при наличии, CSV с историей.
2. Программа проверяет формат файла и обязательные поля каждой строки.
3. По истории строится профиль клиента: количество операций, медиана, 95-й перцентиль, известные страны, устройства и категории.
4. Для каждой корректной новой операции проверяются антифрод-правила.
5. Баллы сработавших правил складываются в риск-скор.
6. По порогам выбирается рекомендация: `APPROVE`, `REVIEW` или `BLOCK`.
7. Программа показывает результаты и сохраняет отчёты. Операции `REVIEW` можно дополнительно одобрить или отклонить вручную.

```text
CSV-файлы
   |
   v
Проверка данных
   |
   v
Профиль клиента + антифрод-правила
   |
   v
Риск-скор и рекомендация
   |
   +------> results.csv
   |
   +------> alerts.csv
   |
   +------> errors.csv

REVIEW -> очередь оператора -> одобрить / отклонить
                         |
                         v
                operator-decisions.csv
```

## 3. Основные части программы

Для учебного проекта достаточно понимать пять частей:

| Часть | Простое объяснение |
|---|---|
| **CSV и проверка данных** | Читает файлы и отбрасывает некорректные строки с записью причины ошибки. |
| **Профиль клиента** | Считает привычные значения по истории клиента. |
| **Скоринг** | Проверяет правила, начисляет баллы и выбирает рекомендацию. |
| **Интерфейс** | Показывает ленту транзакций и очередь ручной проверки. |
| **Отчёты** | Сохраняет результаты, алерты, ошибки и действия оператора. |

## 4. Где это находится в коде

### C++

- `cpp/src/main.cpp` — запуск программы и чтение аргументов командной строки.
- `cpp/src/csv_io.cpp` и `cpp/include/fraudguard/csv_io.hpp` — чтение CSV, проверка записей и запись отчётов.
- `cpp/src/engine.cpp` и `cpp/include/fraudguard/engine.hpp` — модели, профиль, правила и расчёт риск-скора.
- `cpp/tests/` — автоматические проверки.

### Kotlin

- `kotlin/src/main/kotlin/fraudguard/model/Models.kt` — основные объекты и статусы.
- `.../csv/CsvCodec.kt` — чтение и разбор CSV.
- `.../engine/ScoringEngine.kt` — профиль, правила и решения.
- `.../service/FraudGuardService.kt` — связывает обработку данных.
- `.../ui/FraudGuardFrame.kt` — окно, лента и очередь оператора.
- `.../io/ReportWriter.kt` — сохранение отчётов.

### Dart

- `dart/lib/models.dart` — основные объекты и статусы.
- `dart/lib/csv_codec.dart` — чтение и разбор CSV.
- `dart/lib/scoring_engine.dart` — профиль, правила и решения.
- `dart/lib/fraudguard_service.dart` — связывает обработку данных.
- `dart/lib/main.dart` — браузерный интерфейс, лента, очередь оператора и экспорт.

## 5. Почему три версии

C++ выполняет исходное требование о реализации ядра. Kotlin повторяет ту же бизнес-логику и добавляет настольный интерфейс. Dart — дополнительное расширение проекта: оно показывает, как ту же логику можно представить в браузере.

Сравнение делается на одинаковых синтетических CSV-файлах и по одинаковым полям: ID транзакции, риск-скор, решение, факторы риска и статус профиля. Браузерная версия не может запускать локальный `fraudguard.exe`; C++ запускается отдельно или из Kotlin Desktop.

## 6. Диаграммы для отчёта

Для учебной защиты достаточно трёх простых диаграмм:

- `uml/use-case.puml` — кто пользуется системой и какие действия выполняет;
- `uml/class-diagram.puml` — главные данные и компоненты программы;
- `uml/sequence.puml` — в каком порядке обрабатывается транзакция и выполняется ручная проверка.

Диаграммы показывают общую идею проекта. Они не обязаны перечислять каждый метод и каждый технический вспомогательный класс из исходного кода.
