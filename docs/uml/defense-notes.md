# Как объяснить проектную часть на защите

## 1. Use Case

«Эта диаграмма показывает двух пользователей системы. Аналитик загружает CSV, запускает анализ, смотрит результаты и сохраняет отчёты. Оператор работает с алертами `REVIEW` и принимает решение — одобрить или отклонить транзакцию».

## 2. Class Diagram

«`Transaction` хранит данные операции. `ClientProfile` описывает обычное поведение клиента по истории. `ScoringEngine` проверяет правила и формирует `TransactionResult`. В результате хранятся риск-скор, исходная рекомендация и факторы риска. `ReportWriter` сохраняет результат в CSV. Для операций `REVIEW` дополнительно фиксируется `ReviewRecord` — решение оператора».

## 3. Sequence Diagram

«Сначала пользователь выбирает файлы. CSV-модуль читает и проверяет строки. Затем антифрод-движок строит профиль, применяет правила, рассчитывает баллы и выбирает решение. Интерфейс показывает результаты. Если появились транзакции `REVIEW`, оператор принимает решение, которое отдельно записывается в отчёт».

## 4. Почему диаграммы упрощены

«Диаграммы показывают основные роли, данные и шаги, а не каждый метод программы. Это помогает понять проект и не перегружает UML деталями конкретной реализации на C++, Kotlin или Dart».
