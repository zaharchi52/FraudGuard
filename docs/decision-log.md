# Журнал проектных решений

| ID | Решение | Почему | Статус |
|---|---|---|---|
| ADR-001 | Формат обмена — CSV UTF-8 с запятой в качестве разделителя. | Простой для просмотра и поддержки без внешней БД. | Принято |
| ADR-002 | C++17 — основная реализация; Kotlin воспроизводит ту же бизнес-логику. | Соответствует учебному заданию и позволяет сравнить языки. | Принято |
| ADR-003 | Риск-скор ограничен диапазоном 0–100; пороги: 0–29 APPROVE, 30–59 REVIEW, 60–100 BLOCK. | Простая объяснимая шкала для MVP. | Принято |
| ADR-004 | `MIN_HISTORY_SIZE = 5`; без достаточной истории не применяются профильные правила. | Снижает нестабильность статистики на очень малом числе наблюдений. | Принято |
| ADR-005 | Для P95 используется метод ближайшего ранга; медиана для чётного n — среднее центральных значений. | Исключает расхождения реализаций C++ и Kotlin. | Принято |
| ADR-006 | `HIGH_AMOUNT` и `UNUSUAL_AMOUNT` взаимоисключающие. | Не начислять два штрафа за один и тот же признак суммы. | Принято |
| ADR-007 | `HIGH_VELOCITY`: не менее 5 валидных новых операций в интервале от текущего timestamp минус 10 минут до текущего timestamp включительно. Исторические строки не участвуют в частотном окне. | Детерминированное поведение и понятный тестовый сценарий. | Принято |
| ADR-008 | Формируются три отчёта: `results.csv`, `alerts.csv`, `errors.csv`. | Разделение результатов анализа, алертов и ошибок ввода. | Принято |
| ADR-009 | Вся демонстрационная информация синтетическая, валюта — EUR. | Не использовать чувствительные платёжные данные. | Принято |

Изменения решений вносить отдельной строкой; не переписывать историю молча.
