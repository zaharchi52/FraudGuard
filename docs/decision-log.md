## Решение: Kotlin GUI и имитация потока (этап 4)

- Kotlin повторяет бизнес-логику C++ и остаётся отдельной реализацией для прямого сравнения результатов.
- Для учебного настольного интерфейса выбран Swing; FlatLaf используется как тема оформления и не заменяет стандартные Swing-компоненты.
- Живая лента воспроизводит строки CSV постепенно; это имитация, не реальный платёжный поток.
- `REVIEW` попадает в очередь оператора. Рекомендация движка и решение оператора хранятся раздельно.
- Из окна можно отдельно запустить пакетную C++-версию, если бинарный файл уже собран.
- Выходные действия оператора сохраняются в `reports-kotlin/operator-decisions.csv`.

## Решение: третий порт и веб-интерфейс (Dart / Flutter)

- Добавить Dart-реализацию скоринга как третью независимую реализацию тех же правил.
- Интерфейс реализовать на Flutter Web: браузерная демонстрация проще для запуска и показа, не требует отдельного desktop-инсталлятора.
- Денежные значения считать через пакет `decimal`, а не `double`, чтобы сохранить десятичную точность.
- Выбор входных CSV и экспорт отчётов выполнять через `file_picker`; содержимое обрабатывается в памяти вкладки.
- Браузер не запускает локальный C++ `.exe`; пакетный запуск C++ остаётся в CLI и Kotlin Desktop.
- UI Dart должен совпадать с Kotlin по ключевым сценариям: поток, пауза, REVIEW, ручное решение и CSV-отчёты.

## Решение: инструменты тестирования (этап 5)

- Для C++ выбран Google Test; CTest используется как средство запуска зарегистрированных тестов. Отдельный smoke test остаётся доступным без сторонних библиотек.
- Для Kotlin выбран JUnit 5 с assertions из `kotlin.test`; Kotest не подключается, поскольку JUnit и Kotest являются альтернативами в формулировке задания.
- Для дополнительной Dart/Flutter Web-версии используется `flutter_test`.
