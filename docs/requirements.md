# SRS — требования к FraudGuard

**Версия:** 1.0 (учебный MVP)  
**Статус:** базовая версия для согласования команды  
**Связанный документ:** [`../VISION.md`](../VISION.md)

## 1. Назначение

FraudGuard — учебный антифрод-движок с пакетным ядром и интерфейсными реализациями. Он читает синтетическую историю и новые транзакции из CSV, проверяет качество данных, формирует статистический профиль клиента, рассчитывает объяснимый риск-скор и записывает результаты и алерты.

Система не подключается к банкам и не блокирует реальные платежи. Решение `BLOCK` — рекомендация прототипа.

## 2. Область и ограничения

### Входит в MVP

- C++17: основная реализация обработки данных и бизнес-логики.
- Kotlin: эквивалентная логика для сравнения результатов и настольный интерфейс Swing.
- Dart/Flutter Web: дополнительный браузерный порт того же скоринга и демонстрационный интерфейс; не заменяет обязательную Kotlin-реализацию.
- CSV-ввод и CSV-вывод в UTF-8 с заголовком и разделителем-запятой.
- Проверка записей, профили клиентов, шесть объяснимых правил, риск-скор 0–100 и три решения.
- Отчёты `results.csv`, `alerts.csv`, `errors.csv`.
- Unit-тесты и эталонные тестовые данные.

### Не входит

Машинное обучение, реальные платёжные данные, сетевые API, БД, банковская интеграция, интерфейс промышленного уровня, автоматическое воздействие на платёж.

## 3. Термины

- **Транзакция / попытка:** одна строка новых входных операций, прошедшая минимальную проверку `client_id` и `timestamp` для участия в подсчёте частоты.
- **История:** прошлые операции из `history.csv`, используемые только для построения профиля; они не включаются в итоговый `results.csv`.
- **Профиль:** агрегированные сведения клиента по валидным историческим строкам.
- **Фактор риска:** сработавшее правило с кодом, баллами и описанием.
- **Холодный старт (`COLD_START`):** нет истории клиента.
- **Ограниченная история (`LIMITED_HISTORY`):** исторических операций меньше `MIN_HISTORY_SIZE`.
- **Полный профиль (`READY`):** исторических операций не меньше `MIN_HISTORY_SIZE`.

## 6. Данные и валидация

### 6.1. Общая схема CSV

Поля обязательны для `history.csv` и `transactions.csv`:

`transaction_id,client_id,timestamp,amount,currency,country,merchant_category,device_id`

- `transaction_id`, `client_id`, `currency`, `country`, `merchant_category`, `device_id`: непустые строки после удаления пробелов по краям.
- `timestamp`: ISO 8601 с часовым поясом; для примеров используется UTC и суффикс `Z`.
- `amount`: конечное положительное десятичное число, десятичный разделитель — точка.
- `currency`: трёхбуквенный код верхнего регистра. В текущем тестовом наборе используется только `EUR`.
- `transaction_id`: уникален в пределах объединённого набора исторических и входных транзакций. Дубликат входной строки отклоняется.
- Сравнение суммы профиля выполняется только для той же валюты. Мультивалютная конвертация не реализуется.

CSV читается с поддержкой стандартного экранирования кавычками; простое разделение строки на запятые не считается достаточным для промышленно корректного CSV-парсера. В учебном наборе значения не содержат запятых.

### 6.2. Поведение при ошибках

- Нет входного файла транзакций, нет обязательной колонки или заголовок не распознан: ошибка файла, ненулевой код завершения.
- Нет файла истории: предупреждение, все клиенты работают без статистического профиля.
- Некорректная отдельная строка: не скорируется, записывается в `errors.csv`, обработка продолжается.
- Дублированный ID: повторная запись отклоняется и диагностируется.
- Ошибка записи обязательного отчёта: сообщение с именем пути и ненулевой код завершения.
- Нельзя присваивать `APPROVE` невалидной транзакции; она должна иметь статус ошибки обработки и не попадать в `results.csv`.

## 7. Правила, скоринг и решения

### 7.1. Статистический профиль

`MIN_HISTORY_SIZE = 5` валидных исторических транзакций на клиента и валюту. При количестве 0 история имеет статус `COLD_START`; при количестве от 1 до 4 — `LIMITED_HISTORY`; от 5 — `READY`.

Для профиля `READY` рассчитываются:

- `transaction_count`;
- медиана исторических сумм;
- 95-й перцентиль сумм;
- множества исторических `country`, `device_id`, `merchant_category`.

Медиана: для нечётного n — центральное значение отсортированного списка; для чётного n — среднее двух центральных. P95: метод ближайшего ранга, индекс `ceil(0.95 * n) - 1` в отсортированном списке с нулевой индексацией. Статистика считается по истории клиента в той же валюте.

### 7.2. Таблица правил

| Код | Условие | Баллы |
|---|---|---:|
| `HIGH_AMOUNT` | Профиль `READY`, `amount >= 5 * median_amount`. | 30 |
| `UNUSUAL_AMOUNT` | Профиль `READY`, `amount > p95_amount`, при этом `HIGH_AMOUNT` не сработал. | 15 |
| `HIGH_VELOCITY` | В наборе новых валидных попыток этого клиента не менее 5 операций в закрытом интервале `[timestamp - 10 минут, timestamp]`, включая текущую. | 25 |
| `NEW_COUNTRY` | Профиль `READY`, страна не встречалась в истории. | 20 |
| `NEW_DEVICE` | Профиль `READY`, устройство не встречалось в истории. | 15 |
| `NEW_CATEGORY` | Профиль `READY`, категория не встречалась в истории. | 10 |

Правила `HIGH_AMOUNT` и `UNUSUAL_AMOUNT` взаимоисключающие. `HIGH_VELOCITY` вычисляется по валидным строкам новых транзакций, включая текущую; исторические записи не входят в частотное окно в MVP. Входной файл может содержать строки не по времени, поэтому расчёт частоты должен опираться на timestamp, а итоговые отчёты могут сохранять исходный порядок.

Правила, зависящие от профиля, не срабатывают для `COLD_START` и `LIMITED_HISTORY`. Отсутствие истории само по себе не начисляет баллов. Для `HIGH_VELOCITY` достаточно валидных `client_id` и `timestamp`; строка с другими ошибками не считается валидной попыткой.

### 7.3. Формула решения

`risk_score = min(100, сумма баллов сработавших правил)`.

| Скор | Решение |
|---:|---|
| 0–29 | `APPROVE` |
| 30–59 | `REVIEW` |
| 60–100 | `BLOCK` |

Риск-скор не является вероятностью мошенничества. Значения предназначены для учебной демонстрации.

## 8. Выходные файлы

### `results.csv`

Одна строка на каждую валидную новую транзакцию. Обязательные поля:

`transaction_id,client_id,timestamp,amount,currency,risk_score,decision,risk_factors,profile_status,processing_status`

`risk_factors` — коды факторов, разделённые `;`; при записи CSV поле должно корректно экранироваться. Если факторов нет, поле пустое. `processing_status` для скорированных строк — `OK`.

### `alerts.csv`

Только строки, которые имеют решение `REVIEW` или `BLOCK`. Поля включают `transaction_id,client_id,timestamp,amount,currency,risk_score,decision,risk_factors`.

### `errors.csv`

Поля: `source_file,line_number,transaction_id,error_code,message`. Если `transaction_id` не удаётся прочитать, оставить поле пустым. Сообщения должны быть понятными и не содержать чувствительных данных.

## 9. Критерии приёмки

- AC-01: приложение компилируется по README и запускается с указанными путями.
- AC-02: схема CSV и валидируемые поля соответствуют разделу 6.
- AC-03: медиана и P95 совпадают с определёнными здесь алгоритмами.
- AC-04: каждое из шести правил имеет отдельный тест.
- AC-05: `HIGH_AMOUNT` и `UNUSUAL_AMOUNT` не срабатывают одновременно.
- AC-06: значения скора 29, 30, 59, 60 и 100 приводят к правильным решениям.
- AC-07: скор не превышает 100.
- AC-08: пятая попытка клиента внутри скользящего 10-минутного окна включает `HIGH_VELOCITY`; проверена граница окна.
- AC-09: `COLD_START` и `LIMITED_HISTORY` не используют профильные правила.
- AC-10: `alerts.csv` содержит только `REVIEW` и `BLOCK`.
- AC-11: ошибочная строка попадает в `errors.csv`, а следующая валидная строка обрабатывается.
- AC-12: на одинаковых тестовых данных C++ и Kotlin возвращают одинаковые решения, скора и факторы риска.
- AC-13: README описывает формат данных, сборку, запуск и ограничения учебной модели.

## 10. Общие определения для команды

- Веса и пороги в этом документе — единый источник истины для C++, Kotlin и дополнительного Dart-порта.
- Изменение правила сначала записывается в `docs/decision-log.md`, затем синхронно обновляются код и тесты обеих реализаций.
- Синтетические данные не должны включать реальные персональные или платёжные сведения.
