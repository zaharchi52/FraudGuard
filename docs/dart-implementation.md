# Реализация Dart / Flutter Web

## Назначение

Dart-версия — третий независимый порт алгоритма скоринга и браузерный демонстрационный интерфейс. Она не заменяет C++ или Kotlin: C++ остаётся пакетным консольным движком, Kotlin — desktop-приложением с запуском C++ batch, Dart/Flutter — веб-интерфейсом для демонстрации в браузере.

## Модули

| Файл | Ответственность |
|---|---|
| `lib/models.dart` | Транзакции, профили, факторы, результаты, ошибки и состояния ручной проверки |
| `lib/csv_codec.dart` | Чтение CSV, проверка схемы, валидация строк, CSV-экранирование |
| `lib/scoring_engine.dart` | Статистический профиль, шесть правил, velocity, риск-скор и решение |
| `lib/fraudguard_service.dart` | Связывает чтение истории, обработку новых строк и скоринг |
| `lib/main.dart` | Flutter UI, имитация потока, операторская очередь и экспорт отчётов |
| `test/scoring_engine_test.dart` | Эталонное сравнение, валидация, cold-start, границы velocity и расширенный conformance fixture |
| `test/workflow_test.dart` | Одноразовые решения REVIEW и неизменность автоматических статусов |

## Единый контракт скоринга

- Минимум истории для профиля `READY`: 5 операций клиента в той же валюте.
- `HIGH_AMOUNT`: сумма >= 5 × медиана; +30.
- `UNUSUAL_AMOUNT`: сумма > p95 nearest-rank и не сработал `HIGH_AMOUNT`; +15.
- `HIGH_VELOCITY`: минимум 5 операций клиента в включительном окне [timestamp − 10 минут, timestamp]; +25.
- `NEW_COUNTRY`: +20; `NEW_DEVICE`: +15; `NEW_CATEGORY`: +10. Эти правила профиля применяются только при статусе `READY`.
- Факторы складываются, итог ограничивается 100.
- 0–29 `APPROVE`; 30–59 `REVIEW`; 60–100 `BLOCK`.
- `decimal` используется для точного сравнения денежных значений. В случае чётного числа значений медианное сравнение выполняется без деления: amount × 2 >= (middleLeft + middleRight) × 5.

## Поведение потока

Сервис сначала валидирует и оценивает весь пакет, после чего UI постепенно выдаёт готовые результаты по таймеру. Это сохраняет batch velocity semantics и позволяет повторять один и тот же демонстрационный набор. Операции `REVIEW` переходят в `PENDING_REVIEW`. Решения оператора — `APPROVED_BY_OPERATOR` или `REJECTED_BY_OPERATOR` — не перезаписывают исходную рекомендацию движка.

## Браузерная безопасность

Приложение не имеет серверного backend. Пользователь выбирает локальные файлы, содержимое обрабатывается в памяти вкладки, отчёты скачиваются обратно в браузер. Web-страница не может запускать локальный C++ `.exe`; для этого предназначена Kotlin Desktop-версия или CLI C++.

## Проверки

Запуск `flutter test` проверяет исходный и расширенный (15 строк) golden fixtures, обработку трёх неверных записей с сохранением одной правильной, границы velocity/P95/5×median, CSV BOM/CRLF/quotes, дубликаты ID и переходы ручной проверки.
