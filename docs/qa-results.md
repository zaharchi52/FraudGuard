Этот документ отделяет проверки, которые уже подтверждены выводом терминала, от проверок, которые ещё нужно выполнить. Не следует отмечать тест как `PASS` без фактического запуска.

## 2. Известные дефекты

- FG-001 — C++ smoke tests ранее использовали `assert()` и могли не проверять условия в Release. Исправлено явными runtime-проверками; CTest 1/1 прошёл.
- FG-002 — Kotlin CSV parser принимал символы после закрывающей кавычки. Исправлено и покрыто JUnit-тестом.
- FG-003 — Dart CSV parser принимал символы после закрывающей кавычки. Исправлено и покрыто Flutter-тестом; локальный повторный запуск должен подтвердить.

## 3. Расширенный набор для межъязыковой проверки

`data/conformance/` содержит 15 синтетических транзакций и эталонный CSV. Набор включает холодный/ограниченный/полный профиль, разные валюты, точные границы P95 и `5 × median`, временное окно `HIGH_VELOCITY`, новые страну/устройство/категорию.

C++ smoke test уже включает пакетную сверку этого набора. В Kotlin и Dart есть соответствующие тесты на общие эталонные данные. Сверка с golden CSV подтверждает совпадение правил и выходных полей; она не доказывает качество модели на реальных банковских данных.

## 4. Что нужно выполнить для закрытия этапа

1. C++: включить Google Test и запустить расширенные GTest unit cases командой из `testing-frameworks.md`.
2. Kotlin: `.\gradlew.bat clean test --rerun-tasks`, затем открыть `kotlin/build/reports/tests/test/index.html`.
3. Dart: `flutter analyze` и `flutter test`.
4. GUI: выполнить ручные сценарии из `manual-acceptance-tests.md`.
5. Сохранить логи и скриншоты в `reports/qa/` или приложить их к отчёту.

**Текущий статус этапа 5: частично подтверждён.** C++ smoke/integration и Kotlin Gradle build подтверждены пользовательскими логами. Полное выполнение Google Test, принудительный прогон JUnit, финальный Flutter analyze/test и ручная проверка интерфейсов должны быть подтверждены отдельно.
